# Web

The static React SPA, and the only web client. `pnpm dev` serves it, and Caddy serves its build. `Dockerfile` builds it into the Caddy image, with `infra/caddy/Caddyfile`, and that image is the `caddy` service.

| Folder | Holds |
|---|---|
| `src/routes/` | File-based routes. Thin: guards and wiring only. `_app` is the signed-in layout |
| `src/features/` | `auth`, `library`, `player` and `settings`, and `dev` for `/dev/components`. `library` holds the generic list hook and screen, the movie source, Play and Retry, and the notifications. `player` holds `/watch/$id` and the playlist query. `settings` holds the Account, Appearance and Library sections, and the scan query |
| `src/lib/` | The API client, the query client, the socket, the theme provider, the router's search serializer, `devOnly` for dev-only routes, `RouterLink` for the patterns, and `app.tsx`, which wires the router and query client |
| `test/` | Vitest with `@testing-library/react` and `msw`, on the real router and query client |

- API access goes only through `api` in `src/lib/api.ts`. The one path written by hand is the socket's, in `src/lib/socket.ts`. An `<img>` cannot use `api`, so `movieImageUrl` there builds the art's URL from the contract's path. The player uses the `playlistUrl` the API answers with, which is under `/streams`, never `/api/streams`.
- Forms validate with schemas from `@workspace/contract`, as `endpoints.login.body`, never with local copies.
- Guards are for the user's experience. The API checks every request.
- A protected route is a child of `_app`, which also keeps the socket open, so nothing connects without a session. Each route sets its own `PageContainer`, so a title's hero can reach the edges. The player stays inside the shell.
- Every library query's key starts with `libraryKey`. Play and Retry refresh them all. A notification refreshes what it can change: every page of the movie library and its facets, through `libraryListKey` and `libraryFacetsKey`, and the notified title's `movieQuery`. So a status on screen is never stale, and the player starts a title once its notification says it is ready, because it asks for the playlist only while the title is ready. Nothing polls the library. Settings asks for the latest scan every second while it is queued or running, and refreshes the library when it ends.
- A library's state lives in the URL. `src/lib/search-params.ts` keeps query values as text, with a repeated key for a list. `validateLibrarySearch` reads them with the contract's library query, one value at a time, and returns a dropped value as `undefined`, because the router lays its result over the raw search. `stripSearchParams` keeps the defaults out of the URL. A filter change resets the page and adds a history entry, search replaces the entry once typing settles, and a slider commits once it settles.
- `useLibraryList` and `LibraryScreen` take a `LibrarySource`, such as `movieLibrary`, so Shows reuse them with a source of their own.
- A data call goes through TanStack Query, so that a 401 reaches `onSessionLost` in `src/lib/app.tsx`, the one path back to login. Anything else that can see a 401, such as `hls.js`, calls the same function. Login and setup call the API directly, because a 401 there is a wrong password. They use the field primitives in a `Card`.
- `redirect` on `/login` only ever holds what `toReturnPath` returns. Add any new path the API serves to its list.
- ffmpeg, Node APIs and server code do not belong here. The build is static files, and the Vite proxy exists only under `pnpm dev`.
- `src/routeTree.gen.ts` is generated and committed. Vite rewrites it when routes change, so do not edit or format it.
- UI comes from `@workspace/ui`: the stylesheet, `@workspace/ui/tokens.css`, and the shadcn primitives on Base UI, as `@workspace/ui/components/button`. Use a pattern from `@workspace/ui/patterns/*` before a primitive, and a primitive before writing an element by hand. Nothing from Radix or another theme library. `components.json` shares `style`, `iconLibrary`, `baseColor`, `rsc` and the `ui` and `utils` aliases with the one in `packages/ui`, so `shadcn add` from here puts primitives there.
- Colors come from the tokens, as `bg-card` or `text-muted-foreground`. `test/no-raw-colors.test.ts` fails on a raw color, such as `text-red-500`, `bg-black` or a hex value. `DESIGN.md` at the root says which token does what.
- The theme is `useTheme` from `src/lib/theme.tsx`, which puts the `dark` class on `<html>`. The script in `index.html` applies it before first paint with the same storage key, so change both together. Caddy's `Content-Security-Policy` allows that script by its hash, and `vite build` fails until the hash in `infra/caddy/Caddyfile` matches, naming the new one.
- Caddy's policy forbids `eval`, `new Function`, inline event handlers, and any origin but the server's own. `src/lib/zod-without-eval.ts` turns off Zod's compiled parsers, so it is the first import of `main.tsx`, and the build keeps modules in import order for it. `pnpm dev` sends no policy, so `pnpm test:browser` is what catches a violation. The `Toaster` primitive takes its `theme` from it.
- Settings shows the Library section to an owner or admin only, for the user's experience. The API refuses a scan from anyone else.
- Patterns navigate through `RouterLink` in `src/lib/router-link.tsx`, which the root route gives `LinkProvider`. The signed-in layout in `_app.tsx` is `AppShell`, and decides which navigation item is active. A pattern that can see a 401, such as `VideoPlayer`, gets `onSessionLost` from the route context.
- `/dev/components` shows every token, primitive and pattern from fixture data, with a theme switch, and only `pnpm dev` serves it. Its player plays a prepared title by its TMDB id, through `/streams`, so it needs a session. A dev-only route takes `beforeLoad: devOnly`, which answers not found in a build, and picks its component with `import.meta.env.DEV` written in the route file, so that Vite drops the page from the build. One that renders primitives imports its page lazily, because Base UI has top-level code that a static import keeps in the build.
- `src/index.css` ends every animation and transition at once under reduced motion, and the primitives rely on it, so a new app must copy that rule.
- Everything works by keyboard and at phone width, in dark and light. Verify UI changes in a browser.
- Tests act as a user does and check what a user sees, not query keys or router state. `test/support/fake-api.ts` serves the library, facets, a movie, Play and Retry, the playlist of a ready title and the latest scan, and changes a title's status as the API does. A test moves a scan on by setting `scan`, as the worker would. `hls.js` is a dev dependency here only so that `test/player.test.tsx` can stand in for it, and that test gives jsdom's video a play state, and every element a size so that Base UI shows a slider's thumb. Sonner keeps toasts in its module, so `test/setup.ts` dismisses them after each test. `apps/api/test` proves the API client, so do not repeat that here.
